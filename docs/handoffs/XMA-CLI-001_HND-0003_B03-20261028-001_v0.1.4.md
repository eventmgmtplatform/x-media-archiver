## Decisión y matriz de compatibilidad

La frontera valida primero semántica, finitud, signo y rango. Para cadenas, `Decimal(value)` evita
que un negativo subnormal pierda el signo al convertirse a `float`; para valores `float` se valida
el valor recibido. Solo después ejecuta exactamente `seconds = float(value)`,
`milliseconds = seconds * 1000` y `round(milliseconds)`. No usa `Decimal.from_float()` para el
redondeo positivo, saturación, sustitutos ni captura indiscriminada.

| Entrada válida | Milisegundos |
|---|---:|
| `0`, `0.0001`, `0.0005` | 0 |
| `0.0015`, `0.0025`, `0.0045` | 2, 2, 4 |
| `"0.0005"`, `"0.0025"`, `"1e-400"`, `"12.5"` | 0, 2, 0, 12500 |

Se conservan los rechazos previos al redondeo de `-0.0001`, `-0.0005`, `-5e-324`, `"-0.0001"`
y `"-1e-400"`. Booleanos, NaN, infinitos y valores fuera del entero SQLite firmado de 64 bits
producen `DiscoveryContractError` con el mensaje constante
`gallery-dl numeric metadata violates the B03 contract`.

Este addendum corrige expresamente la afirmación incompatible de HND v0.1.3: REWORK-003 no
conservaba el comportamiento histórico de los empates positivos `float`; `0.0005` y `0.0025`
producían 1 y 3 ms por `Decimal.from_float()`. REWORK-004 restaura 0 y 2 ms. HND v0.1.3 permanece
como evidencia histórica y no se reescribe.
