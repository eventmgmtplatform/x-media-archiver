### R-04 — JSON pasa por un renderizador de presentación

**Contrato:** PRM §4.4, JSON estable.  
**Código:** [cli.py L130–155](https://github.com/eventmgmtplatform/x-media-archiver/blob/44c28f3fd2bedfa99123e0ae74a73e5bf940d1b2/src/xma/cli.py#L130-L155).

`console.print(json.dumps(...))` usa Console por defecto sin desactivar markup ni wrapping. Contenido válido con etiquetas Rich dentro del texto de una publicación puede alterarse o producir un error de markup; el ajuste al ancho también puede romper una cadena JSON larga. Los tests con texto simple no cubren estas entradas. Se contrastaron los defaults de la versión bloqueada [Rich 14.3.4](https://github.com/Textualize/rich/blob/v14.3.4/rich/console.py#L627-L640) y su [procesamiento de markup](https://github.com/Textualize/rich/blob/v14.3.4/rich/console.py#L1436-L1447).

**Corrección:** salida JSON cruda, preservada y parseable, con regresiones de texto entre corchetes, Unicode y cadenas largas. Hallazgo estático; esta auditoría no ejecutó el caso.

### R-05 — Errores externos y de persistencia incompletamente normalizados

**Contrato:** PRM §§4.2 y 4.4.  
**Código:** [gallery_dl.py L101–107](https://github.com/eventmgmtplatform/x-media-archiver/blob/44c28f3fd2bedfa99123e0ae74a73e5bf940d1b2/src/xma/adapters/discovery/gallery_dl.py#L101-L107), [cli.py L98–125](https://github.com/eventmgmtplatform/x-media-archiver/blob/44c28f3fd2bedfa99123e0ae74a73e5bf940d1b2/src/xma/cli.py#L98-L125).

Not-found y fallo transitorio se colapsan en error genérico. La CLI captura InvalidIdentityError/DiscoveryError, pero conflictos del catálogo, SQLite y fallos de filesystem pueden escapar; `mkdir` está fuera del try.

**Corrección:** categorías/normalización y códigos documentados, mensajes sin traceback por defecto, tests CLI para conflicto, ruta no escribible y fallo externo. No ocultar errores inesperados indiscriminadamente.

### R-06 — Idempotencia frente a variantes efímeras

**Contrato:** PRM §4.3.  
**Código:** [adapter L163–172](https://github.com/eventmgmtplatform/x-media-archiver/blob/44c28f3fd2bedfa99123e0ae74a73e5bf940d1b2/src/xma/adapters/discovery/gallery_dl.py#L163-L172), [servicio L80–90](https://github.com/eventmgmtplatform/x-media-archiver/blob/44c28f3fd2bedfa99123e0ae74a73e5bf940d1b2/src/xma/application/discovery.py#L80-L90), catálogo B02 de activos inmutables.

La URL completa del proveedor se transmite a `MediaAsset.variants` y se persiste. Dos observaciones del mismo activo con una URL efímera diferente pueden generar IdentityConflictError aunque la identidad lógica sea la misma. La suite prueba datos idénticos, no rotación de variantes.

**Corrección:** definir campos estables frente a efímeros y su actualización/sanitización; probar dos sync del mismo activo con variantes cambiantes. No se afirma que se haya encontrado un secreto real ni que una URL firmada concreta se haya filtrado en logs. La proyección JSON omite variantes; persistencia y logging son superficies distintas.

### R-07 — Defensa del límite y contrato de cursor

**Contrato:** PRM §§4.2 y 6.7.  
**Código:** [DiscoveryService.inspect](https://github.com/eventmgmtplatform/x-media-archiver/blob/44c28f3fd2bedfa99123e0ae74a73e5bf940d1b2/src/xma/application/discovery.py#L41-L43), [mapper](https://github.com/eventmgmtplatform/x-media-archiver/blob/44c28f3fd2bedfa99123e0ae74a73e5bf940d1b2/src/xma/adapters/discovery/gallery_dl.py#L199-L207).

La aplicación devuelve el batch del proveedor sin contrastar su conteo con el límite solicitado por el llamador. El adaptador actual limita los registros y el DTO valida su propio requested_limit, pero no sustituyen la defensa de la frontera de aplicación exigida. El cursor es siempre None; falta una prueba/documentación explícita de la limitación o paginación observada.

**Corrección:** validación defensiva y prueba de proveedor que excede el límite solicitado; documentar cursor no disponible si corresponde, sin inventar una capacidad de paginación.
